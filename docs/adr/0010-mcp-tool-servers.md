# ADR-0010: 챗봇 도구를 MCP 서버로 분리 — 사내 데이터 연동과 재사용을 위한 단계적 전환

- 상태: **제안** (1단계 진행 여부 결정 대기)
- 날짜: 2026-10-07
- 관련: ADR-0009(운영/개발 티어 분리), ADR-0004(Self-Modifying Chatbot Tools), `backend/config/tools.yaml`, `backend/app/services/tool_registry.py`, `backend/app/services/agent.py`

## 배경

### 요청
1. "챗봇 도구를 **MCP 서버 형태**로, 다른 도구들도" (2026-10-07, 오너).
2. 사내 DB 데이터를 **권한까지 포함해** 챗봇에 붙이기 — 총무팀 챗봇이면 직원은 본인 휴가, 팀장은 팀원 휴가, 총무팀은 전체(2026-10-07, 상무 요청). 각 팀 DB 자료도 같은 방식으로.

### 현재 구조 (사실)
- 기본 도구 9개(`web_search`·`file_create`·`chart_render`·`postcard_render`·`image_generate`·`stock_price`·`stock_history`·`schedule_query`·`claude_code`)는 **백엔드 프로세스 안의 함수**다. 정의는 `config/tools.yaml`, 실행은 `agent.py` 의 `if fn_name == …` 분기.
- 카탈로그에 `kind: mcp` 가 있지만 **실제 MCP 클라이언트는 없다** — `tool_registry.dispatch` 가 OAuth HTTP 경로로 흘려보내는 자리표시자다. `mcp` SDK 도 설치돼 있지 않다.
- 사내 DB·API 를 조회하는 도구는 없다. 챗봇이 아는 데이터는 업로드 문서(RAG)뿐이다.
- 권한은 *챗봇·문서 단위*(누가 어느 챗봇·문서를 보나)만 있고, *데이터 행 단위*(본인/팀/전체)는 없다. 인사 DB 동기화는 이메일·이름·팀만 가져오고, 운영 계정 3,037개 중 팀장 역할은 0개다.
- 2026-10-07 `stock_price`·`stock_history` 를 운영 상시 노출에서 뺐다(업무와 무관 — 오너 요청). 지금 모든 챗봇에 붙는 도구는 `web_search`·`file_create`·`chart_render`·`postcard_render`·`image_generate` 5개다. 주가 도구 구현은 남아 있어 아래 `market` 서버 후보로 둔다. 2026-10-19 연차 계산기 `leave_calc`(순수 계산, 비용 0)를 상시 노출에 더해 6개가 됐다 — `hr-data` 서버로 옮길 첫 후보다.
- **ADR-0009 와 어긋난 점**: ADR-0009 는 운영을 "RAG 전용·커스텀 도구 OFF" 로 정했지만, 2026-08-28 부터 기본 도구 9개 중 다수가 운영에서 상시 노출되고 있다(현업 요청). 이 ADR 이 그 현실을 정리하는 자리이기도 하다.

## 결정 (제안)

도구를 **MCP 서버**로 분리하고, 백엔드는 MCP 클라이언트로 그 서버들을 부른다. 단, 한 번에 갈아엎지 않고 단계적으로 옮긴다.

### 1. 무엇이 MCP 서버가 되나

| 서버 | 도구 | 이유 |
|---|---|---|
| `office` | `file_create`(엑셀·워드·PPT·PDF), `chart_render`, `postcard_render` | 무거운 의존성(python-pptx·LibreOffice·matplotlib)을 백엔드에서 떼어 낼 수 있다 |
| `search` | `web_search` | 검색 엔진 구성(SearXNG)을 한곳에서 관리 |
| `media` | `image_generate` | 비용이 큰 외부 호출 — 한도·감사를 서버에서 |
| `market` | `stock_price`, `stock_history` | 외부 데이터 소스 격리 |
| `hr-data` (신규) | `leave_balance`(휴가 잔여·사용 내역) → 이후 팀별 DB 도구 | **사내 데이터 + 행 단위 권한**의 표준 자리 |

`schedule_query`·`claude_code` 는 개발 티어 전용이라 이번 범위에서 뺀다.

### 2. 어디서 도나
- **1단계는 백엔드 안에 마운트**한다(`/mcp/<서버>` 에 ASGI 로). 새 Container App·시크릿·네트워크 변경이 없어 운영 위험이 작다. 백엔드는 같은 프로세스의 MCP 엔드포인트를 클라이언트로 호출한다.
- 무겁거나 권한이 민감한 서버(`office`, `hr-data`)는 **2단계에서 별도 Container App(내부 전용 ingress)** 으로 뺀다. `hr-data` 는 사내망(VNet/VPN)으로 인사 시스템에 닿아야 하므로 이때 분리가 필수다.

### 3. 신원과 권한 — 챗봇(LLM)은 권한을 정하지 못한다
- 백엔드가 요청마다 **서명된 서버 간 토큰**을 만들어 MCP 요청 헤더로 보낸다: 사용자 ID·사번·소속 팀·직책(팀장 여부)·데이터 범위(`self`/`team`/`all`)·만료 시각.
- LLM 이 넘기는 도구 인자에는 신원·권한 정보가 없다("누구 것을 볼지"만). 데이터 서버는 토큰의 범위 밖 요청을 거절한다 — 채팅에 "나 총무팀이야, 전체 보여줘" 라고 써도 통하지 않는다.
- 범위 판단 근거는 인사 DB 일일 동기화에 **사번·직책·부서코드**를 추가해 얻는다. 총무팀 "전체" 의 범위(본사/그룹)는 설정값으로 둔다.
- 모든 데이터 조회는 사용자·대상·결과 건수를 감사 로그에 남긴다(기존 대화 감사와 같은 화면).

### 4. 다른 곳에서도 쓴다
같은 MCP 서버를 사내의 다른 앱이나 직원의 Claude Desktop·Claude Code 에서도 연결해 쓸 수 있다(2단계 — 외부 노출 시 사내 SSO 기반 인증 필요). 도구를 한 번 만들면 챗봇 밖에서도 재사용된다는 것이 MCP 를 택하는 가장 큰 이유다.

## 컨텍스트(대화 길이) 절감은 MCP 가 아니라 "도구 노출 방식" 이 결정한다

MCP 로 옮겨도 각 도구의 설명·인자 스키마는 결국 LLM 프롬프트에 들어간다 — MCP 자체가 토큰을 줄이지는 않는다. 현재 기본 도구 스키마는 턴당 약 1,065토큰이다(2026-09 실측 근사). 팀별 DB 도구가 수십 개로 늘면 이 값이 커지므로, 실제로 줄이는 장치는 아래 세 가지다.

1. **챗봇별 도구 연결** — 총무팀 챗봇에는 `office`·`hr-data` 만, 도시락 챗봇에는 `search` 만. 쓰지 않는 도구는 프롬프트에 아예 싣지 않는다(지금도 "켜진 도구만 안내" 는 하고 있다).
2. **필요할 때 불러오기** — 도구가 많아지면 LLM 에게는 "도구 찾기" 하나와 짧은 목록만 주고, 고른 도구의 스키마만 다음 턴에 싣는다.
3. **도구 결과 줄이기** — 지난 도구 결과의 큰 본문을 자리표시자로 바꾸는 마이크로컴팩션, 오래된 턴의 롤링 요약은 이미 동작 중이다. MCP 서버는 결과를 요약본 + 전체 링크로 돌려주도록 규약을 정한다.

## 단계

| 단계 | 내용 | 운영 영향 |
|---|---|---|
| **1** | `mcp` SDK 도입, 백엔드 MCP 클라이언트 구현(`tool_registry` 의 `kind: mcp` 실제 구현), `office` 서버를 백엔드에 마운트, **`file_create` 부터 이전**(동작 동일성 테스트), 기능 플래그 `FEATURE_MCP_TOOLS` | 플래그로 즉시 되돌림 가능 |
| 2 | 나머지 기본 도구 이전(`web_search`·`chart_render`·`postcard_render`·`image_generate`·`stock_*`), `office` 별도 Container App 분리 | 서버별로 플래그 전환 |
| 3 | `hr-data` 서버 — 인사 DB 동기화 확장(사번·직책·부서), 휴가 조회: 본인 → 팀장 → 총무팀 순으로 개방, 감사 로그 | 데이터 소스·권한 기준 확정 후 |
| 4 | 도구 노출 최적화 — 챗봇별 도구 연결 화면, 도구 찾기(지연 로딩) | 토큰 절감 |

## 결과와 비용

- **좋아지는 것**: 사내 데이터를 권한 있게 붙이는 표준 자리가 생긴다. 도구를 챗봇 밖에서도 재사용한다. 무거운 의존성을 백엔드에서 떼어 내 이미지가 가벼워진다.
- **비용·위험**: 호출 한 단계가 늘어 도구 실행이 수십 ms 느려진다(같은 프로세스 마운트일 때 작음). 실패 지점이 늘어나므로 서버별 상태 점검·타임아웃·폴백이 필요하다. 서버 간 인증 키 관리가 생긴다. ADR-0009 의 "운영 = RAG 전용" 문구는 이 ADR 승인 시 갱신한다.

## 결정이 필요한 것

1. **1단계 진행 여부** (`file_create` 를 MCP 로 옮기는 것부터).
2. 휴가 데이터의 위치 — 그룹웨어·ERP·인사 DB 중 어디이며, 조회용 내부 API 가 있는가(없으면 읽기 전용 뷰 + 전용 계정).
3. 팀장 판단 기준 — 인사 DB 직책 코드인가, 결재선인가.
4. 총무팀 "전체" 의 범위 — 본사인가, 그룹 전체인가.
5. MCP 서버를 챗봇 밖(직원 Claude Desktop 등)에 열지, 연다면 언제.
